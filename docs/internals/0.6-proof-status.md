# 0.6 proof status and deferred soundness goals

0.6 is now scoped as a feature, library and stabilization release; see the
[release notes](0.6-release-notes.md) and [revised roadmap](roadmap.md).
The broad original proof goal is deferred to future research, not discharged.
This page retains the gap assessment against that original goal. References to
its gates or blockers describe unfinished soundness work, not prerequisites for
the smaller release. In particular, proving the production checker implementation
correct is **not** added as a gate. The implementation may remain trusted and
be tested against the specified rules. Counts of theorems, passing tests or PRs
are not a percentage of the required soundness result.

## Principal blocker to the original soundness goal

There is not yet one specified-Core typing judgment whose derivations establish
runtime ownership and borrow safety across the required language. Pure typing,
quantity control traces and guarded heap operations are useful existing parts,
but proving them separately does not establish their composition for arbitrary
Core programs accepted under the specified rules.


The native Loan64 mixed checker now shares source typing and recursive resource
projection in one actual history. Its binding-retaining machine derives an
exact reader-frame/lease inventory at every prefix and derives explicit Lend
callback origin typing from the input judgment. Literal-Decide named Index
also has a constructed read execution under explicit local allocation/slot
alignment. These narrow the composition gap: general runtime value/control-stack
interpretation, dynamic bounds, owner accounting and the original consistency
obligations remain unfinished. See the current [work record](../../proofs/FULL_KERNEL_WORK.md).

Recursive runtime capture/erasure alignment is now preserved at every machine
prefix. A dynamic IfLt/Index bridge derives its read guard from actual compared
slots, and a checked Buffer/Lend function has source typing and exact safe
execution/accounting for every bounded count/index with representable allocation
size. These are components and a parameterized function result, not the missing
whole-language fundamental theorem.

All-prefix numeric value/capture/heap bounds now construct I64 typing of
actual Index integers at the original closed Loan64 source type. Scalar Lend
readers also admit an actual-value closing of the continuation body. Literal
and dynamic Index execution obtain heap validity, reader inventory and numeric
bounds from actual reachability; source/control typing and allocation/slot/loan
association remain input invariants of the local statements. The common
source/resource/value/heap fundamental theorem is still unfinished.

Dependent Lend resource projections now agree with both retained continuation
owner aliases and actual close/activation transitions. Free through either
alias reaches the same heap object; its guard is characterized by the remaining
reader frames, including nested readers. The source judgment preserves the
remaining code's original ghost result type and its projection has zero further
owner demand. General admission must still supply the local code/slot/frame
associations, exclude consuming an owner with an outer reader, and connect all
actual tail executions to those abstract resource traces. These local results
do not establish whole-kernel ownership soundness or native refinement.

Actual nested-reader return now resumes a source-authorized outer Borrow using
the token that survives the inner close. Source permission comes from the
specialized dependent continuation check; original captured slots identify its
concrete owner, and reachability supplies token distinction and liveness.
Both retained bindings and Borrow execute before the original-type tail entry.
Checking rejects reborrow through either restored-owner alias if no outer
source permission remains. The general closed-admission/control/slot/resource
fundamental theorem and the original whole-kernel obligations remain open.

Fresh allocating readers now reconstruct their scalar widths, declared Buffer
type conversion and separate first-result linear obligation from the actual
Loan64/resource checks. Actual allocation supplies a live owner of the right
length, distinct from the leased original owner, and a derived Free guard.
Byte-size overflow remains explicit. This is a local value/heap interpretation,
not exclusive ownership or the missing whole-language fundamental theorem.

That fresh result now flows through a constructed sixteen-step reader and
continuation execution that separately frees it and the original owner. The
source projection then has zero demand for both resources and the remaining
code keeps its original ghost type. Byte overflow and an outstanding outer
reader of the old owner remain explicit outcomes; this is not the general
admission-to-runtime ownership or arbitrary-tail resource theorem.

An all-prefix owner-provenance invariant now includes every saved frame and
recursive closure capture. No old captured owner can alias the next allocation,
including released owners. Actual allocation events reconstruct current owner
length/payload without a supplied allocation snapshot. This read-only heap
provenance does not grant liveness/exclusive authority to retained aliases or
interpret all dependent source lengths; the common source/resource/value/heap
fundamental theorem and whole-kernel obligations remain unfinished.

A fresh owned reader result now flows into a second actual Lend and named
Borrow/Index. Source typing supplies the strict bound and exact reader type;
twenty constructed transitions supply the result slot, concrete allocation
length and both lease lifetimes. No read-success/output-typing or allocation-
association oracle is supplied. Byte overflow remains explicit and the current
input code/control/frame association still needs the general fundamental
theorem. This does not complete arbitrary dependent computation/ownership or
native implementation refinement.

For this returned-Buffer path, inner close, both owner releases and scalar
return now have a constructed thirty-two-step execution at the original outer
result type. Owner provenance and concrete reader inventory derive the fresh
Free guard. Old-owner reader conflicts and byte overflow remain explicit
outcomes; general admitted-program exclusion/interpretation and the whole-
kernel fundamental theorem remain unfinished.

Actual natural arguments now close dependent function-body types at their
observed numerals while the machine retains original source provenance. The
mixed checker supplies the initial empty value closing; reachability supplies
numeric bounds and actual entry preserves direct scalar slots and old loans.
Effectful argument origins are not assumed convertible to the returned numeral.
General closure/control/capture/heap interpretation remains unfinished.

A computed U64 argument can now drive a retained-variable allocation body.
Six real transitions construct a Buffer whose length matches the dependent
signature at the observed argument, with source-derived fill width and runtime-
derived freshness. Original argument provenance is retained and byte overflow
remains explicit. General source-result interpretation and closure/control/

The value closing also handles I64 arguments and a computed second closure
that captures its earlier U64 size. A closed resource-admitted curried program
computes size and fill with separate Free/arithmetic effects, then uses the
generic retained-slot allocation proof. Its actual Buffer length/payload are

original effectful source result annotation to its actual-value instance.
General source-result/control/resource interpretation remains unfinished.

Evidence in the current code and statements:

- `CoreBridgeBetaTyping.HasType` handles the existing pure scalar/array/evidence
  and function grammar. It does not have `Buffer`, `Ref`, `Alloc`, `Lend` or
  `Free` rules and its variable lookup is unrestricted ghost-mode lookup.
- `HeapLeases.Step` requires liveness, lease authority and no active borrow at
  deallocation. Its invariant theorem cannot by itself establish that typing
  supplies those preconditions.
- `Quantity.Control` and its erasure theorem concern projected resource traces.
  They are not the full Core runtime interpretation of those traces.
- The earlier `ScopedLend` result is scalar by syntax. But `Core.infer`'s `Lend`
  rule calls `outlived`, which permits `Buffer`, `Back` and data `Ind` results as
  well as scalars. `core_lower` passes both the reader result and the original
  owner to the continuation. An owned reader result must therefore be a second
  independently accounted-for resource, not a scalar or an alias of the owner.
- `MirCallerValidation.Accepted` checks agreement of independently supplied
  source and target graphs. Its conditional theorem is not a proof that the
  general lowering function produces such a target for every typed source.

The existing direct contribution is a declarative mixed-result `Lend` rule on the
**existing Core constructor graph**, reusing the heap/lease semantics. Its
continuation typing consumes resources by their identity, clears every lexical
alias on consumption, and permits arbitrary finite allocation/free sequencing.
This same judgment now includes Lend recursively in continuations and handles
any selected capability among multiple live owners; alias/borrow authority is
proved from the lexical context. Readers can return a scalar or allocate a fresh one-cell buffer
while the original owner's lease is active. The same judgment now distinguishes
owner identities, scalar value slots and consumed names, carries the actual
scalar result through subsequent Lends, and proves bounded scalar results
together with ownership safety under explicit initial value bounds. Closing an owned-result lease transfers the new buffer and the original
owner as two distinct capabilities; a scalar result retains only the original
capability and adds its actual scalar value. Primitive step guards and safe transfer
must follow from the typing and environment invariants, not be supplied as an
assumed safe event trace or an `Accepted` certificate.

This is a direct extension for an omitted specified rule, not the full solution.
It still restricts buffer shape and reader expressions. Continuation nesting
creates sequential lease regions, not nested active-reader Lends. The remaining common
judgment must account for recursive data/field ownership, `Back`, more general
reader results and contexts, recursion, and their substitutions and runtime
interpretations. Extending syntax without those connections would not close
the principal blocker.

## Structural connection still required

The largest remaining difference is not another missing scalar test. Actual
`Core.infer` shifts dependent variable types, distinguishes runtime/erased
lookup, and `dependent_lend` substitutes the borrowed original and returned
owner into the reader/continuation before inference. Pure `Raw.Beta.HasType`
already has dependent typed substitution, while the graph ownership judgment
uses owner/scalar slots. A common proof must relate those interpretations; merely
renaming the ownership judgment `HasType` would not do so.

The open scalar computation bridge now interprets mixed lexical scalar entries
as the existing pure typing context and provides its closing substitution.
Owners and consumed names are unavailable in that context. Its generic
substitution result applies to existing open Raw terms and dependent result
types. A finite executable graph grammar retains actual scalar let binders and
realizes their computation in the existing pure reduction relation, feeding the
value into the same ownership continuation rule.

This is the first direct reuse of that pure substitution/evaluation proof at
this ownership execution boundary. Immediate owned-argument binding additionally transfers the selected capability
to a formal parameter while invalidating its earlier lexical aliases. This is
not general substitution of owned functions, Buffer/Ref dependent types or
Borrow values in the full Raw typing language.
The executable grammar is structurally terminating first-order I64 lets; there
is no assumed successful evaluation in typing. General higher-order termination,
arithmetic traps and U64/I64 distinctions cannot be inferred from this fragment.

The next runtime rule is ordinary owned application, which differs materially
from Lend. Actual `Core.infer` requires a linear lambda parameter to be used
exactly once; `uses` counts the runtime argument and any captured use of the
original owner separately. Therefore an immediate Buffer1 application cannot
simply add another usable alias as Lend does. The common judgment transfers
lexical authority to the new formal parameter, tombstoning every old alias of
that capability while preserving the concrete owner list and unrelated captures.
This supplies a resource-sensitive binding rule for actual App/Lam/Var nodes,
not a separate evaluator or an assumption that an arbitrary substitution is safe.

The runtime fragment still requires a direct lambda, an owned variable argument,
a closed one-cell Buffer annotation. The common judgment now has scalar and
owned result modes: returning the last capability preserves its live identity,
while releasing all other tracked resources. A fresh consuming continuation can
then receive that returned capability without reviving old lexical aliases.
This does not cover higher-order/partial application, general owned-producing
App arguments, or dependent Buffer lengths and result-type substitution. The
producer/consumer theorem composes their execution relations at a fresh
capability boundary. A recursive syntactic application extension now connects
that boundary to actual direct Buffer1 App/Lam nodes with an App-shaped owned
argument. The producer accounts for the entire current resource inventory,
returning one capability; the body receives only its parameter;
existing Types/Exec derivations supply the leaves. This does not justify
dropping captures or interpreting arbitrary open/dependent applications.
The next framed extension supports retained owner and scalar captures using an
explicit static prefix partition: the producer cannot access the reserved frame,
and the body cannot access consumed aliases. Frame preservation is derived from
execution and conservation, not a supplied untouched-trace premise. This closes
the singleton-body restriction for that checked partition, not arbitrary
partition inference/coherence, general closures or dependent substitution.
The framed judgment is now closed under the existing Free, allocation,
scalar/owned Lend, scalar-let and owner-binding continuations. Calls beneath
those constructors participate in the same totality, heap safety and accounting
statements rather than stopping at an opaque old derivation. Structural
expansion preserves the previous typing and execution on exact graphs; it does
not add new dependent types or eliminate the explicit partition plan.
A plan-free lexical execution bridge now separates that static proof plan from
the runtime meaning of the supported graph. Concrete captured owner/scalar
bindings remain in their lexical positions, including consumed aliases; the
static context revokes access instead of pretending the runtime deleted them.
Simulation into an independently deterministic lexical evaluator gives the
same value, exact events and final heap for any supported typed plan with the
same initial interpretation. Existing totality supplies execution, and safety
transfers to every plan-free execution of the fragment. This closes the
fixed-plan operational ambiguity, not partition inference or the remaining
dependent-language coverage gaps.
The first runtime-length extension now refines the existing uniform read-only
heap with exact object lengths and read indices. Open U64 index expressions
have lexical substitution laws; source Buffer/Ref annotations and Lt evidence
are interpreted against the same closing values. A sized source subset derives
allocation/read/free safety and dependent owner-result lengths. Its
closing-instance judgment is separate from the previous full Buffer1 fragment:
it supports prefix-partitioned direct framed calls and fresh-result owned Lend,
but does not generalize arbitrary
nonuniform buffers, Store, or full dependent Pi/result substitution. The
checked example uses one graph across arbitrary runtime n/i inputs rather than
replacing n with constants in the graph.
The sized judgment now also supports direct owned transfer, framed owned
application and a restricted owned-result Lend whose fresh result length is
independent of the original buffer length. These rules participate recursively
in the same safe-execution and accounting theorem. Static prefix partitions
revoke producer/body authority without changing runtime lexical positions;
the plan-free evaluator remains deterministic. Retained captures preserve
their lengths and payloads. The reader is still specifically a fresh allocation
initialized by an in-bounds read, not an arbitrary effectful reader, and the
judgment remains semantic closing-instance typing rather than full dependent
Pi preservation.
Those remaining omissions remain part of the common-typing gap rather than
optional checker implementation refinement.

The common binary Data judgment now supports computed direct-lambda application
with independent static prefix partitions of Data and sized Buffer capabilities.
Argument typing consumes only its selected slots; the continuation receives the
actual returned tree plus retained captures, while every consumed alias loses
authority. General execution lemmas preserve the retained trees' stored field
interpretations and the Buffers' exact lengths, so body safety is derived rather
than assumed. The same totality/every-run theorem includes this rule, including
applications under Case's pending parent shell. This closes a resource-binding
composition gap in the fixed binary fragment, not general dependent Pi
substitution, partition inference, recursive functions, native refinement or
whole-language exact accounting. See
[the rule and proof boundary](../../proofs/COMMON_DATA_PARTITION.md).

That same common judgment now has an allocation-ID conservation theorem over
all its rules: releases plus the whole returned tree footprint equal tracked
inputs plus fresh allocations, per identity. The returned footprint uses the
same final stored-tree witness as ownership. Every nonreturned tracked identity
is freed exactly once; final live-domain equality additionally requires initial
coverage by input resources and frame. This is allocation accounting for the
restricted binary Data/sized Buffer fragment, not logical exactly-once use of
empty capabilities, lease-token accounting or full-language quantity soundness.
The [accounting proof boundary](../../proofs/COMMON_DATA_ACCOUNTING.md) records

Constant-result binary Case now also has a recursive source-view typing judgment.
It checks the scalar/Data motive against both arbitrary derivable branch bodies,

The old empty-constructor-only nil restriction is no longer required by this

connects to the adapted abstract evaluator; by itself it does not establish

dependent-motive support. The original strict
adapter and checked production snapshot remain intact. See the
[source rule boundary](../../proofs/COMMON_DATA_SOURCE_RULES.md).

An independent inductive source constructor-view execution relation now covers
this fixed binary fragment. Forward correspondence preserves values, traces and
final abstract states; reflection requires source typing. Typed totality and
accounting transfer from the common Data runtime, and determinism extends those
guarantees to every observed source run. The model shares abstract heap/store
operations and scalar execution with the common runtime. This is not parser or
export fidelity, production-checker soundness, concrete layout/allocator safety,
or full compiler refinement. See the
[source execution boundary](../../proofs/COMMON_DATA_SOURCE_EXECUTION.md).


The symbolic Buffer judgment is now connected to fixed binary Tree source

derive the existing concrete source typing, actual source execution totality,
and safe steps, final heap validity and resource accounting for every run.
Case field binding and split application preserve lexical index shifts and
retire consumed aliases. Direct uniform Buffer allocation and release now recurse
through the common judgment, preserving Data and pending frames and revoking
every selected Buffer alias. One symbolic Alloc → Case → Free → Data derivation
has all-length totality and every-run accounting; split application also retains
the Buffer across Case/Drop and releases it later.
This remains the binary Tree, constant-motive fragment; Store, general dependent Pi, recursive functions, arbitrary readers and
full native soundness remain open. See [mixed source typing](symbolic-core-typing.md#mixed-binary-data-source-typing).


The common compact Data target now integrates the existing compact Core runtime
